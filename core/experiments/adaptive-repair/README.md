# CORE 0.1.2-adaptive-repair.1

One continuing CORE experiment, no CDCL and no instance-specific rules. Starts from the exact archived BOUNDARY100 and immediate-repair patch. The new opt-in schedule scores up to 24 guard pivots per round by original CNF violations, checks conditional propagation against the certified active set, and gives a candidate at most 20 ms of repair. Retains only strict source-violation improvements; retries with changed seed utility. Four rounds/eight attempted pivots, same total 120 ms / 12% remaining budget as immediate repair. No unverified message exported; conditional states remain private; full original SAT model checked separately. An unsuccessful repair is not UNSAT. This is within-formula adaptive scheduling, not cross-instance learned mathematics. Fixed limits are deliberately specified before input generation.

Controls: BOUNDARY, BOUNDARY-REPAIR, ADAPTIVE-REPAIR; one CPU, same 5 s solve budget, 3 balanced repetitions, separate prefix and terminal audits. Two known hard formulas are diagnostic only. 100 fresh formulas from the prior ten generators plus 30 from three separate transfer generators (random5, exact-cover incidence, implication-ring mixed). These generators are new to this panel, not a claim of globally unseen mathematical families. Freeze source/harness before seed generation; no tuning on the new panel. Report paired gains/losses, PAR2, E2E, and independently accepted direct adaptive models. No speedup or success claim until CI confirms it. Main unchanged.
