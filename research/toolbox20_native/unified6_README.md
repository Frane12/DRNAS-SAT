# UNIFIED6 — utility learning and composition
Frozen C++20 UNIFIED4 remains unchanged; experimental Python research layer only. 30 training, 30 independent calibration, 50 fresh synthetic holdout instances. Training extracts proof-backed signed macros from complete and partial traces; a second training-only pass harvests multi-step deductions from combined learned prefixes and native proofs. Matching uses indexed signed clause patterns, necessary width-count filter, bounded matching, and two passes allowing reuse of earlier macro consequences. Every prefix checked against original clauses; models against original CNF, UNSAT via standard DRAT or independently checked structural certificate plus RUP prefix. No CDCL fallback.
Four arms, same solver, 5 s wall decision cap including pilot/restart/matching, rotating order, one logical CPU: base (direct), staged (0.24 s pilot then restart if unresolved; no memory), static (same pilot plus indexed memory with untrained order), learned (same pilot and matcher with calibration-derived utility order). 0.24 s memory matching cap, 500 attempts per rule, at most 100 new clauses, two passes. Short pilot success bypasses memory. Per-rule reward uses shared calibration outcome and cost, not causal per-rule measurement. Calibration scores and catalog are frozen before testing. No family labels passed to solver/matcher; used only to draw/partition and report. Two holdout families absent from training/calibration; larger uniform 3-SAT cases test transfer within family. Training and independent proof-checking costs separate from decision cap. One run per arm; do not claim statistically significant improvement. A chain hit means premises use a previously emitted macro conclusion, not invention of a new theorem. No main changes.
